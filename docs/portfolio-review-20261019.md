# 포트폴리오 개선·검수 기록

확인일: 2026.10.19

## 디자인 방향

채용 담당자가 실무 경험, 시각 디자인, 구현 역량을 빠르게 비교할 수 있도록 기존 민트·화이트, Pretendard·Buenard, 작은 모서리와 문서 스크롤을 유지했습니다. 기본 HTML·CSS·JavaScript 구조를 사용합니다. 디자인 변화 5 / 모션 3 / 정보 밀도 4로, 작품을 중심에 두고 장식적 움직임을 추가하지 않았습니다.

| 이전 | 개선 | 이유 |
| --- | --- | --- |
| 첫 대표작이 자동차 분야 3개 | 카베이·투썸플레이스·브랜드 레퍼런스 | 서로 다른 강점을 먼저 확인 |
| 15개 화면을 동등한 목록으로 제공 | 대표작 5개와 추가 작업, 롤렉스 2방향 묶음 | 선택 부담과 중복 인상 완화 |
| 미리보기 아래의 작업 설명 | 미리보기 위의 작업 과정·Figma·전후 비교·공개 코드 | 화면과 설명의 연결 |
| 역할·기간 10–11px | 핵심 메타 정보 13–14px | 담당 범위의 가독성 확보 |
| 공통 비율의 그래픽 썸네일 | 가로 배너 4:1, 상세 4:5, SNS 1:1 | 작품 유형에 맞는 화면 면적 사용 |
| 도구 이름 나열 | 실제 작업 범위 설명 | 설명 가능한 역량으로 전달 |

## 사례 자료와 수치의 범위

- 카베이: 보관된 리뉴얼 전후 화면, 현재 공개용 시연본, 작성자가 제공한 메뉴 클릭 집계표.
- 클릭 합계: 1,932 + 881 + 787 + 290 + 101 + 93 + 51 + 46 = **4,181회**.
- 핵심 3개 메뉴: 3,600 / 4,181 × 100 = **86.1%**(소수 첫째 자리 반올림).
- 이는 메뉴 클릭 분포입니다. 집계 기간, 이전 기간의 수치, 유입량, 상담 완료 수가 없어 상승률이나 전환율로 표현하지 않았습니다.
- 브랜드 레퍼런스: 공개 저장소의 README·목록 로딩·URL/로컬 저장 구조를 확인했습니다. 2026년 GDWEB 카탈로그 크기는 `catalog/build-report.json`의 1,148,444 bytes / gzip 246,029 bytes를 사용했습니다. 이미지·폰트·실제 전송 시간은 이 수치에 포함되지 않습니다.
- 롤렉스: 공개용 `app.js`의 검색, 조건 선택, 관심 모델 저장 및 메뉴 키보드 처리를 확인했습니다.
- 전자명함: vCard 다운로드, 시스템 공유 지원 분기, 공유 이미지 다운로드, 후기 상담 폼 오류 상태를 소스에서 확인했습니다. 회사 시연 화면의 실적은 포트폴리오 성과에 합산하지 않았습니다.
- 투썸플레이스: 기존 Figma 기반 구현을 유지하고, 실제 데스크톱·모바일 화면에 디자인 설명을 붙였습니다.
- 협업 분담·정확한 제작 기간·공개 이력서는 추가 근거가 없어 기재하지 않았습니다.

## 확인 환경과 동작

Codex 내장 브라우저의 뷰포트로 확인했습니다. 실제 휴대폰·Safari에서의 검수 기록은 아닙니다.

| 환경 | 확인 내용 | 결과 |
| --- | --- | --- |
| 1440 × 900 | 대표작 전환, 비활성 슬라이드 포커스 제외, 작업 바로가기 | 선택한 프로젝트와 URL 일치 |
